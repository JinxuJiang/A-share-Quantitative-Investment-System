# 03.1 模型训练层设计原理与逻辑架构
> 定位：将 Tushare 因子宽表转换为可冻结、可增量、可回测的 Quarterly PIT V2 预测链。
---
## 一、层级职责
模型训练层负责：
- 加载技术和财务因子
- 构建 open-to-open 收益标签
- 过滤 ST 和训练集低利润候选
- 生成季度训练、验证和预测边界
- 训练 LightGBM 季度固定模型
- 输出原始和平滑 PIT 预测
- 管理 Freeze 状态
- 调参、稳健性验证和 production 参数晋升
- 多周期预测融合

不负责：
- 财务 PIT 和因子清洗
- 回测成交、费用和止损
- 组合优化
---
## 二、为什么使用 Quarterly PIT V2
传统滚动训练容易产生一个问题：同一个历史日期在不同运行中可能由不同训练截止日、不同模型或不同数据版本重新预测。

V2 的目标是建立稳定信号链：

```text
一个自然季度
    │
    ├─ 季度开始前确定训练和验证数据
    ├─ 训练一个固定模型
    ├─ 整个季度复用该模型
    └─ 历史预测生成后冻结
```

核心收益：
- 同一季度模型口径固定
- 预测时点清晰
- 可做 as-of 一致性验证
- 每周更新只追加新日期
- 历史回测不会被后续重训无声改变

V1 Walk-forward 入口、切分器和训练器已退役，当前代码只保留 V2 主链路。

## 四、标签设计
### 4.1 可执行时点
T 日因子使用 T 日收盘前可知信息。完整因子在 T 日收盘后形成，因此不能假设以 T 日收盘价成交。

```text
T日因子 ──→ T+1开盘买入 ──→ T+(horizon+1)开盘卖出
```

### 4.2 标签公式
```python
entry_price = open[t + 1]
exit_price = open[t + horizon + 1]
label = exit_price / entry_price - 1
```

20 日模型：

```text
T+1 开盘买入
T+21 开盘卖出
```

### 4.3 Gap设计
训练、验证和预测之间保留：

```text
gap = horizon + 1
```

目的：
- 防止训练集最后一个标签进入验证期
- 防止验证标签进入预测季度
- 保证不同区间的未来收益窗口不重叠
---
## 五、季度切分
### 5.1 切分结构
```text
训练窗口        Gap        验证窗口        Gap        预测季度
默认3Y  ─────────────────→ 默认2M ─────────────────→ YYYYQn
```

### 5.2 固定季度模型
模型周期用 `YYYYQn` 标识，例如：

```text
2026Q1
2026Q2
2026Q3
```

预测季度内不重新训练。

### 5.3 Start/End语义
| 参数 | 语义 |
|:---|:---|
| `start_date` | 预测输出起点，不截断所需历史训练窗口 |
| `end_date` | 数据截止日和本次as-of日期 |

不能把 `start_date` 理解为模型只能读取该日之后的数据。
---
## 六、股票池设计
### 6.1 ST过滤
正式路径：

```text
01数据/data/tushare_data/st_status.parquet
```

状态不为 0 的股票不进入当日截面。

### 6.2 利润过滤
`profit_filter_pct: 0.2`：
- 只作用于训练和验证
- 过滤净利润 TTM 最低 20% 候选和其中亏损股票
- 不作用于预测截面

设计原因：模型可以减少对持续亏损尾部样本的学习，但正式预测仍面对完整可交易股票池。

### 6.3 缺失值
因子层已经完成主要截面清洗。训练层仍需要：
- 对齐因子共同日期和股票
- 删除标签缺失样本
- 保留 LightGBM 可处理的合理特征缺失
- 记录实际特征列表
---
## 七、模型设计
### 7.1 LightGBM
当前 production 使用 LightGBM 回归模型。

选择原因：
- 适合表格型截面特征
- 可捕捉非线性和交互
- 对缺失值较稳健
- 训练速度和可解释性平衡较好
- 支持 early stopping 和特征重要性

### 7.2 Huber目标
正式配置使用 Huber 损失，降低极端收益样本对拟合的影响。

### 7.3 特征重要性
特征重要性用于：
- 发现长期主导因子
- 比较不同季度稳定性
- 排查单一因子异常垄断

不能把树模型重要性直接解释为因果贡献。

## 八、Freeze设计
### 8.1 状态结构
```text
experiments/{exp_id}_v2/state/
├── freeze_manifest.json
└── models/
    └── model_YYYYQn.pkl
```

### 8.2 配置哈希
Manifest 保存关键配置哈希。相同实验 ID 如果更换关键参数，训练器拒绝继续追加。

### 8.3 增量规则
```text
已有预测日期 ──→ 跳过
已有季度模型 ──→ 复用
缺失预测日期 ──→ 追加
新季度       ──→ 训练并冻结
```

### 8.4 Reset边界
更换模型、因子或参数时应使用新实验 ID。

`--reset-freeze` 只用于明确重建同一个实验状态，不是日常更新参数的工具。
---
## 九、预测平滑
每只股票独立进行固定半衰期指数平滑：

```text
smoothed[t] = alpha × pred[t] + (1-alpha) × smoothed[t-1]
```

当前默认：

```yaml
smooth_halflife: 10
```

平滑用于降低信号波动和换手率，不保证提高原始 IC。
---
## 十、多周期融合
### 10.1 输入
```text
5d smoothed_predictions
20d smoothed_predictions
60d smoothed_predictions
```

### 10.2 流程
1. 按 `date + stock_code` 取共同样本
2. 每个模型每日做截面 Rank 标准化
3. 计算历史日度 IC
4. 使用基准 horizon 对权重进行滞后
5. 用历史 IC 均值生成动态权重
6. 输出兼容回测层的融合预测

### 10.3 防泄漏
如果基准为 20 日模型，T 日权重不能使用最近 20 个交易日尚未完全兑现的标签。

## 十一、输入输出契约
### 11.1 输入
| 数据 | 路径 |
|:---|:---|
| 技术因子 | `02因子库/processed_data/factors/technical/` |

### 11.2 输出
```text
experiments/{exp_id}_v2/
├── config.yaml
├── quarterly_splits.parquet
├── predictions.parquet
├── smoothed_predictions.parquet
├── summary.parquet
├── models/
├── feature_importance/

```

V2 不生成独立 `live_predictions.parquet`。所有当时可生成的预测都进入单一 PIT 主链。

## 十二、潜在风险
| 风险 | 控制 |
|:---|:---|
| 未来标签泄漏 | open-to-open + Gap |
| 财务未来信息 | 因子层PIT对齐 |
| 历史预测漂移 | Freeze |
| 参数过拟合 | 代表季度调参 + 非重合季度验证 |
| 单季度模型异常 | summary和特征重要性检查 |
| 配置重复漂移 | production晋升规则 |
| 融合权重泄漏 | IC权重按horizon滞后 |
