# 05.2 输出层工程实现与规范
> 本文档描述正式 Alpha 发布脚本、文件字段、版本规则和下游读取方式。
---
## 一、目录与文件职责
```text
05输出层/
├── publish_alpha.py
├── README.md
└── exports/                    # 运行时生成，Git忽略
    ├── releases/
    │   └── {release_id}/
    │       ├── stock_alpha.parquet
    │       └── manifest.json
    └── current.json
```

| 文件 | 职责 |
|:---|:---|
| `publish_alpha.py` | 校验实验、转换字段、生成 release、更新 current |
| `stock_alpha.parquet` | 后续仓库使用的标准截面 Alpha |
| `manifest.json` | 单个 release 的来源、口径和校验信息 |
| `current.json` | 当前默认正式 release 指针 |
---
## 二、发布命令
以下命令在项目根目录执行：

```powershell
python 05输出层/publish_alpha.py `
  --exp-id lgbm20_tushare_profit20_v2 `
  --release-id alpha_20d_tushare_profit20
```

参数：

| 参数 | 必填 | 说明 |
|:---|:---:|:---|
| `--exp-id` | 是 | `03模型训练层/experiments/` 下的实际实验目录名 |
| `--release-id` | 是 | 新的、不可重复的正式发布 ID |

ID 只允许英文字母、数字、点、下划线和连字符。
---
## 三、输入
发布器固定读取：

```text
03模型训练层/experiments/{exp_id}/config.yaml
03模型训练层/experiments/{exp_id}/smoothed_predictions.parquet
```

必需预测字段：

```text
date
stock_code
pred_score_smooth
```

`horizon_days` 从 `config.yaml` 的 `data.label.horizon` 获取。

单模型实验直接使用自身 horizon；融合实验使用融合命令中 `base-idx` 对应模型的 horizon。发布器对两类实验使用同一套输入契约。

发布器不读取 `04回测层/reports/`。回测报告只用于发布前的人工验收。
---
## 四、转换规则
```text
date              → signal_date
pred_score_smooth → alpha_score
每日截面百分位     → alpha_rank
配置 horizon      → horizon_days
```

`alpha_rank` 使用当日截面百分位：
- 最高预测分数对应 1
- 分数越低，百分位越接近 0
- 并列值使用平均排名
---
## 五、输出 Schema
| 字段 | 类型 | 约束 |
|:---|:---|:---|
| `signal_date` | datetime64[ns] | 非空 |
| `stock_code` | string | 非空 |
| `alpha_score` | 浮点数 | 非空、有限值 |
| `alpha_rank` | float32 | `(0, 1]` |
| `horizon_days` | int16 | 正整数 |

主键：

```text
signal_date + stock_code
```

发布前必须保证主键不重复。
---
## 六、manifest.json
主要字段：

| 字段 | 说明 |
|:---|:---|
| `schema_version` | 当前为 `stock_alpha_v1` |
| `release_id` | 正式发布 ID |
| `source_exp_id` | 来源训练实验 |
| `source_file_sha256` | 来源平滑预测校验值 |
| `source_config_sha256` | 来源配置校验值 |
| `source_git_commit` | 发布时 Git commit |
| `source_git_dirty` | 发布时工作区是否有未提交修改 |
| `horizon_days` | 模型周期 |
| `data_start` / `data_end` | Alpha 日期范围 |
| `execution_lag_trading_days` | 最早执行滞后 |
| `row_count` | 输出行数 |
| `output_sha256` | 正式 Alpha 文件校验值 |
---
## 七、current.json
格式：

```json
{
  "schema_version": "stock_alpha_current_v1",
  "release_id": "alpha_20d_tushare_profit20",
  "manifest": "releases/alpha_20d_tushare_profit20/manifest.json",
  "updated_at": "2026-07-31T16:00:00+08:00"
}
```

组合仓库默认先读取 `current.json`，再读取其中 release 对应的 manifest 和 Parquet。复现历史结果时应显式指定 release，不依赖 current。
---
## 八、完整性与写入规范
发布器检查：
- 实验目录、配置和预测文件存在
- `horizon_days` 有效
- 关键字段非空
- `alpha_score` 不含无穷值
- 主键无重复
- release 不存在

发布过程先写临时目录，全部完成后再改名为正式 release。`current.json` 使用临时文件替换，避免读取到半写状态。
---
## 九、开发规范
- 不把 `actual_return` 加入正式输出
- 不在输出层重新计算模型预测
- 不覆盖历史 release
- 修改字段时必须升级 `schema_version`
- 大型 release 和 `current.json` 均属于运行时产物，不提交 Git
- 下游通过文件读取，不导入训练层内部类
