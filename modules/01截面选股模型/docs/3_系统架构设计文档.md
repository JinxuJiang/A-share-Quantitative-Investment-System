## 一、系统概览
### 1.1 系统定位
本系统是面向 A 股日频截面的多因子选股研究与回测平台。

系统从 Tushare 原始数据开始，经过 PIT 财务对齐、因子计算、LightGBM 季度模型训练和双轨回测，最终发布可追溯、可由后续仓库读取的正式截面 Alpha。

当前不把组合优化描述为已完成能力。行业中性、换手率约束和优化器仍属于后续正式接入范围。

### 1.2 核心准则
> 逻辑领先于代码，相关性服务于因果。

| 原则 | 说明 |
|:---|:---|
| PIT优先 | 任一时点只能使用当时已经公开的信息 |
| 可执行标签 | 收益标签从 T+1 开盘开始计算 |
| 历史冻结 | 已生成信号不能因后续运行被静默重算 |
| 存算分离 | 原始数据、处理数据、模型和报告分层存储 |
| 单向依赖 | 上层读取下层产物，下层不反向依赖上层 |
| 真实披露 | 文档区分已实现、部分兼容和待实现能力 |

## 二、架构原则
### 2.1 存算分离
数据按层级持久化：

```text
01数据/data/tushare_data/          # 原始与兼容数据层
02因子库/processed_data/           # 日频宽表与因子层
03模型训练层/experiments/          # 模型、预测和冻结状态
04回测层/reports/                  # 分析与回测报告
05输出层/exports/                  # 正式Alpha release与指针
```

收益：
- 任一层可独立重算
- 上游数据更新不要求立即重跑全部下游
- 实验可以追溯实际输入与配置
- 大型 Parquet 和模型文件不进入 Git

### 2.2 低耦合设计
模块之间通过文件契约通信：

```text
Module 1 ──Parquet──→ Module 2
Module 2 ──Parquet──→ Module 3
Module 3 ──Parquet──→ Module 4
Module 3 + Module 4验收 ──文件契约──→ Module 5
Module 5 ──stock_alpha_v1──→ 后续组合仓库
```

禁止：
- 数据层直接计算策略收益
- 因子层依赖具体模型实现
- 模型层修改历史原始数据
- 回测层重新定义训练标签

### 2.3 One Factor, One File
每个因子独立存储：

```text
processed_data/factors/
├── technical/ret20.parquet
├── technical/std20.parquet
├── financial/roe.parquet
└── financial/pe.parquet
```

优势：
- 新增或删除因子不影响其他文件
- 单因子可以独立验证和重算
- 训练层通过目录扫描构建特征集合
- 因子轴和缺失率易于检查

主要文件：


#### 3.1.3 数据流
```text

├── daily/adj_factor/daily_basic
```

### 3.3 Module 3: AI训练层（Alpha Combiner）
#### 3.3.1 职责
- 构建特征和 open-to-open 标签
- 生成季度训练、验证和预测边界
- 训练 LightGBM 季度固定模型
- 保存连续 PIT 预测链
- 管理 Freeze 状态
- 搜索、验证和晋升模型参数
- 融合多周期预测

V1 Walk-forward 入口、切分器和训练器已从当前代码删除。

#### 3.3.2 类图
```text
DataConstructorV1
├── load_features()
├── calculate_labels()
└── build()
        │
        ▼
QuarterlySplitterV2
├── build_splits()
└── to_frame()
        │
        ▼
QuarterlyTrainerV2
├── run()
├── train_quarter()
├── save_predictions()
├── smooth_predictions()
└── manage_freeze_state()
        │
        ▼
LightGBMModel
├── fit()
├── predict()
└── get_feature_importance()
```

`DataConstructorV1` 仅保留历史文件名，是当前 V2 共用实现。

#### 3.3.3 V2 Quarterly PIT 训练流程
```text
模型季度：2025Q2

历史训练窗口        Gap      验证窗口       Gap      2025Q2预测
约3年数据 ───────────────→ 约2个月 ───────────────→ 固定模型
```

关键规则：
- 每个自然季度训练一次
- 季度内所有交易日使用同一模型
- Gap 默认 `horizon + 1`
- `predictions.parquet` 是唯一 PIT 主预测链
- `smoothed_predictions.parquet` 使用固定半衰期
- Freeze 模式复用季度模型并追加缺失日期

#### 3.3.4 标签生成
```python
entry = open[t + 1]
exit = open[t + horizon + 1]
target = exit / entry - 1
```

#### 3.3.5 多周期融合
```text
5d smooth ─┐
20d smooth ├─→ 日截面Rank标准化 ─→ 滞后IC权重 ─→ ensemble
60d smooth ┘
```

以基准模型 `horizon + 1` 作为 IC 权重滞后长度，避免使用尚未兑现收益；当前 20d 基准使用 21 个交易日。

### 3.4 Module 4: 回测层（Analysis & Backtest）
#### 3.4.1 职责
- 计算 Rank IC、IR 和分层收益
- 将预测分数转换为月度调仓列表
- 模拟手续费、仓位、成交和止损
- 输出净值、交易和调仓报告

#### 3.4.2 架构图
```text
predictions.parquet
        │
        ├─→ AlphalensAnalysis
        │     ├─ IC
        │     ├─ quantile return
        │     └─ turnover
        │
        └─→ SignalGenerator
              ├─ 主板过滤
              ├─ ST过滤
              ├─ 数据长度过滤
              ├─ T+1开盘涨停过滤
              └─ Top N
                    │
                    ▼
             BacktraderStrategy
              ├─ 90%等权仓位
              ├─ 手续费
              └─ 止损
```

#### 3.4.3 当前策略口径
| 项目 | 当前值 |
|:---|:---|
| 调仓频率 | 每月第一个交易日 |
| 持仓数量 | 20 |
| 股票范围 | 60/00主板 |
| 总仓位 | 90% |
| 手续费 | 0.2% |
| 显式滑点 | 未设置 |
| 有效止损 | 20% |

#### 3.4.4 当前迁移边界
- Alphalens 已兼容 V2
- Backtrader 读取 V2 主预测链和 Tushare 正式 ST 状态
- 旧实盘信号脚本已退出主链路
- 第四层仍需完成 Tushare 三周期正式回测验收

#### 3.4.5 组合优化约束（待完善）
计划能力：
- 行业中性
- 单股权重上下限
- 换手率约束
- 风险暴露约束

这些能力当前不属于默认回测实现。

### 3.5 Module 5: 输出层（Alpha Publisher）
#### 3.5.1 职责
- 发布人工选定且已经回测验收的训练实验
- 将 `pred_score_smooth` 映射为稳定的 `alpha_score`
- 生成每日截面 `alpha_rank`
- 剔除 `actual_return` 和训练内部字段
- 保存不可覆盖 release、manifest 和 current 指针

#### 3.5.2 架构图
```text
experiments/{exp_id}/
├── config.yaml
└── smoothed_predictions.parquet
          │
          │ 04层回测验收通过
          ▼
publish_alpha.py
          │
          ├─ 字段校验
          ├─ 截面排名
          ├─ SHA256
          └─ 原子发布
          ▼
exports/
├── releases/{release_id}/
│   ├── stock_alpha.parquet
│   └── manifest.json
└── current.json
```

#### 3.5.3 下游边界
组合仓库默认读取 `current.json` 指向的 release；历史复现显式指定 `release_id`。输出层不计算组合权重，也不负责下单。

### 4.2 Parquet文件格式规范
#### 4.2.1 行情宽表格式
```text
time        000001.SZ  000002.SZ  600000.SH
2026-07-27      12.34       8.91       10.20
2026-07-28      12.40       8.88       10.31
```

适用文件：
- `open.parquet`
- `high.parquet`
- `low.parquet`
- `close.parquet`
- `volume.parquet`

#### 4.2.2 因子宽表格式
```text
time        000001.SZ  000002.SZ  600000.SH
2026-07-27       0.32      -0.41        1.05
```

要求：
- index 或 `time` 表示交易日
- 股票列使用标准带交易所后缀代码
- 值为清洗后的浮点因子

#### 4.2.3 预测结果格式
```text
date        stock_code  pred_score  actual_return  model_period  fold_id
2026-07-27  000001.SZ      0.1234          NaN      2026Q3        26
```

平滑文件使用 `pred_score_smooth`。

#### 4.2.4 正式 Alpha 格式
```text
signal_date  stock_code  alpha_score  alpha_rank  horizon_days
2026-07-28   000001.SZ        0.0123      0.8732            20
```

正式输出不包含 `actual_return`。主键为 `signal_date + stock_code`。

## 附录
### A. 术语表
| 术语 | 说明 |
|:---|:---|
| PIT | Point-in-Time，只使用当时可知信息 |
| TTM | Trailing Twelve Months，滚动十二个月 |
| IC | 预测分数与未来收益的截面相关性 |
| Rank IC | 预测排序与收益排序的 Spearman 相关性 |
| Freeze | 冻结历史季度模型和预测，只追加缺失日期 |
| As-of | 指定数据在某个截止日时的可知状态 |
| Gap | 防止标签跨越数据边界的交易日隔离 |
