# 00.2 项目文档架构
> 本文档定义整个多因子项目的文档体系，包括命名规范、内容边界和维护方式。
---
## 一、文档体系总览
本项目采用双轨制文档体系：
| 位置 | 用途 | 读者 | 内容特点 |
|:---|:---|:---|:---|
| `docs/` | 详细设计文档 | 维护者、研究者 | 原理、接口、检查点、踩坑和变更历史 |
| 各模块 `README.md` | GitHub 快速说明 | 使用者、代码维护者 | 当前状态、目录、命令和主要输入输出 |

README 必须描述当前可运行状态；`docs/` 可以保留历史决策，但必须明确标注已退役内容。

## 四、GitHub README 规范
每个模块 README 保持以下结构：

```markdown
# XX 层名称
> 一句话定位

## 当前状态
说明当前可用能力和已知限制

## 目录结构
代码与运行时目录

## 核心逻辑
关键数据流和设计原则

## 快速开始
可直接执行的命令

## 输入输出
路径、格式和字段

## 详细文档
链接到 docs/ 下三篇文档
```

README 中的命令必须与当前代码参数一致；历史命令只允许出现在明确标注的历史章节中。

## 五、文档格式规范
### 5.1 紧凑原则
- 标题与正文之间最多一个空行
- 段落之间最多一个空行
- `---` 用于一级章节分隔
- 不为装饰目的堆叠空行

### 5.2 表格格式
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| time | datetime64 | 交易日 |
| stock_code | string | 标准股票代码 |

要求：
- 第一列不额外加粗
- 表格内容简洁
- 当前值和计划值不得混写

### 5.3 代码块
- 标明语言类型
- 命令注明执行目录
- 路径使用项目相对路径
- 不写个人机器绝对路径

### 5.4 状态描述
功能状态统一使用：
- 已完成：当前代码与产物均已验证
- 部分兼容：可以运行但仍使用旧路径或旧口径
- 待完成：当前入口不可用于正式结果
- 已退役：代码已删除，仅 Git 历史可恢复
