# 01.3 数据层运维与变更日志
> Tushare 数据层检查点、运维流程和变更记录。
---
## 一、关键检查点
### 1.1 每次更新必查
| 检查项 | 通过标准 |
|:---|:---|
| 交易日历 | 最大日期覆盖目标截止日 |
| 行情三表 | 覆盖全部开市日 |
| 个股行情 | 抽样最新日等于最后开市日 |
| ST状态 | 最大日期等于最后开市日 |
| 停牌状态 | 最大日期等于最后开市日 |
| 财务分区 | 无FAIL；最新披露期允许WARN |
| 更新日志 | 记录本次结束时间和范围 |

### 1.2 当前迁移验收基线
2026-07-29 数据层验收：

```text
截止日：2026-07-28
主检查：PASS=12 / WARN=0 / FAIL=0
行情开市日：4022
个股行情文件：5468
ST状态：4022 × 5535
停牌状态：4022 × 5535
财务分区：264
```

财务详细检查中，2026Q2 四张表各有一个 incomplete disclosure WARN。该报告期仍在披露阶段，属于可解释状态。

注意：总报告的 `warn=0` 与财务详细报告的 4 个 WARN 口径不一致，后续应统一汇总逻辑。

## 二、运维操作
### 2.1 首次初始化
```powershell
python 01数据/tushare_data_main.py --full
```

执行后检查：

```text
01数据/data/tushare_data/logs/validation_report.json
```

### 2.2 每周更新
```powershell
python 01数据/tushare_data_main.py --weekly
```

周更完成后必须继续执行因子层重建。周更本身不会更新 `02因子库/processed_data/`。

### 2.3 指定截止日
```powershell
python 01数据/tushare_data_main.py --full --end-date 20260728
```

用途：
- 避免盘中未收盘数据
- 复现 as-of 数据状态
- 故障恢复时缩小范围

### 2.4 财务历史版本补抓
```powershell
python 01数据/tushare_data_main.py --refresh-financial-versions
```

只在旧目录缺少历史报告类型和修订版本时执行一次。

### 2.5 故障恢复
1. 查看最后一个成功分片或财务分区
2. 确认没有其他下载/重建进程
3. 保留已完成文件
4. 重新执行原命令
5. 下载器自动跳过已完成部分
6. 重新运行验证

## 三、存储与性能
当前本机规模约：

| 目录 | 规模 |
|:---|---:|
| `01数据/` | 约4.3GB |
| 个股行情文件 | 5468个 |
| 财务完整分区 | 264个 |

耗时受以下因素影响：
- Tushare限频和积分权限
- 是否已有原始分片
- 财务版本是否需要全量补抓
- 本地磁盘和Parquet压缩速度

不在文档中固定承诺全量耗时；以每次日志为准。
---
## 四、故障排查
| 现象 | 检查 |
|:---|:---|
| 任务反复请求同一日期 | 分片未成功写入或校验失败 |
| 最新行情落后 | 目标截止日不是最后完整交易日 |
| 财务分区WARN | 判断是否为当前披露期 |
| 状态表轴明显变小 | 检查股票池和交易日历 |
| Parquet无法读取 | 删除单个损坏目标并重跑对应分区 |
| 因子仍是旧日期 | 继续执行02层重建 |
