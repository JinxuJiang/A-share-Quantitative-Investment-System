# 01.2 数据层工程实现与规范
> 本文档描述 Tushare 数据引擎的接口、存储格式、配置和开发注意事项。
---
## 一、运行入口
以下命令均在项目根目录执行。

### 1.1 Token配置
在以下文件保存一行 Tushare Pro token：

```text
01数据/tushare_token.txt
```

也可以设置环境变量：

```powershell
$env:TUSHARE_TOKEN = "<token>"
```

Token 文件已被 `.gitignore` 排除。

### 1.2 全量下载
```powershell
python 01数据/tushare_data_main.py --full
```

指定截止日：

```powershell
python 01数据/tushare_data_main.py --full --end-date 20260728
```

不带参数运行只显示帮助，不会下载数据。

### 1.3 每周更新
推荐统一入口：

```powershell
python 01数据/tushare_data_main.py --weekly
```

等价入口：

```powershell
python 01数据/tushare_weekly_update.py
```

二者不要在同一次更新中重复执行。

### 1.4 历史财务版本刷新
仅用于旧 Tushare 数据目录缺少 `report_type=5` 等历史版本时：

```powershell
python 01数据/tushare_data_main.py --refresh-financial-versions
```

## 二、核心API
### 2.1 TushareDataEngine
```python
from Base_TushareEngine import TushareDataEngine

engine = TushareDataEngine()
```

核心方法：
| 方法 | 说明 |
|:---|:---|
| `download_metadata()` | 股票信息、交易日历、行业映射 |
| `download_market_data(start, end, missing_only, build)` | 行情抓取与兼容文件构建 |
| `download_financial_data(start_period, end_period, overwrite)` | 财务四表完整版本 |
| `download_status_data(start, end)` | ST和停牌状态 |
| `validate_all(end_date)` | 数据层总验收 |

### 2.2 行情下载两阶段
第一阶段：按交易日抓取。

```text
daily + adj_factor + daily_basic
          │
          ▼
raw/market/{dataset}.parquet
或 raw/market/{dataset}_shards/
```

第二阶段：按股票构建兼容行情。

```text
raw market
    │
    ▼
等比前复权 + 字段统一
    │
    ▼
market_data/{code}.parquet
```

### 2.3 财务分区
目录：

```text
financial_full/{table}/{YYYYMMDD}.parquet
```

要求：
- 四张表分别落盘
- 保留报告类型和公告版本
- 同一股票同一报告期允许多行版本
- 不在数据层执行跨表公告日合并
- 分区写入必须原子化

### 2.4 每周更新器
周更顺序：

```text
元数据
  → 行情原始分片
  → 行情兼容文件
  → 财务最新分区
  → ST/停牌状态
  → validate_all
```

周更只更新 01 层，不会自动重建 02 层宽表和因子。

## 三、数据规范
### 3.1 个股行情
位置：

```text
01数据/data/tushare_data/market_data/{code}.parquet
```

主要字段：
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| time | datetime64 | 交易日 |
| open | float | 前复权开盘价 |
| high | float | 前复权最高价 |
| low | float | 前复权最低价 |
| close | float | 前复权收盘价 |
| volume | float | 成交量 |
| amount | float | 成交额 |
| turnoverRate | float | 换手率兼容字段 |
| total_mv | float | 总市值 |
| circ_mv | float | 流通市值 |

股票文件名使用标准代码：

```text
000001.SZ.parquet
600000.SH.parquet
```

### 3.2 财务完整版本
位置：

```text
01数据/data/tushare_data/financial_full/
```

关键标识字段：
| 字段 | 说明 |
|:---|:---|
| ts_code | 股票代码 |
| ann_date | 公告日期 |
| f_ann_date | 实际公告日期 |
| end_date | 报告期 |
| report_type | 报告类型 |
| update_flag | 更新标记 |

版本选择规则属于因子层，数据层只保证字段和版本完整。

### 3.3 ST状态
```text
01数据/data/tushare_data/st_status.parquet
```

格式：
- index：交易日
- columns：股票代码
- value：0=正常，1=ST

Tushare 不区分输出状态值 1 和 2；旧 QMT 的 `2=*ST` 口径不再沿用。

### 3.4 停牌状态
```text
01数据/data/tushare_data/suspend_status.parquet
```

格式：
- 0：正常
- 1：停牌

## 四、断点续跑与原子写入
### 4.1 行情分片
长时间全量任务按固定交易日数量写分片。已存在且通过检查的分片自动跳过。

### 4.2 财务分区
财务按表和报告期独立检查：
- 文件存在且结构正常时跳过
- 空分区和异常分区允许重试
- `overwrite=True` 时重新写入

### 4.3 锁文件
财务重建使用：

```text
.financial_prepare.lock
```

锁用于防止两个进程同时重建相同下游财务宽表。

### 4.4 临时文件
写入流程：

```text
目标目录临时文件 → Parquet写入完成 → 原子替换正式文件
```

## 五、验证规范
### 5.1 元数据
- `stock_basic` 非空
- 交易日历覆盖截止日
- 股票信息和行业映射存在

### 5.2 行情
- daily、adj_factor、daily_basic 覆盖全部开市日
- 个股文件数量合理
- 抽样股票最新日期等于最近开市日

### 5.3 状态
- ST和停牌状态最大日期等于最近开市日
- 行列轴与股票池基本一致

### 5.4 财务
- 分区可以读取
- schema 稳定
- 没有非法重复键
- 最新披露期允许因披露未完成产生 WARN

验证报告：

```text
data/tushare_data/logs/validation_report.json
data/tushare_data/logs/financial_full_validation.json
```

## 六、开发注意事项
### 6.1 不要提前做PIT去重
不能按同一报告期只保留最早公告行。修订版本必须保留到因子层。

### 6.2 不要用自然日代替交易日
行情覆盖、状态前向填充和截止日判断必须以 `trade_cal` 为准。

### 6.3 不要盘中混入未收盘日
全量或周更应使用最后一个完整交易日作为 `end_date`。

### 6.4 复权重建
新增复权因子后，历史前复权价格会发生比例调整。行情兼容文件应基于最新原始分片重建。

### 6.5 最新财务期WARN
披露期内行数远低于历史中位数时产生 WARN 是合理的。不能为了消除 WARN 伪造或前向复制原始财务分区。

## 八、常见问题
| 问题 | 可能原因 | 处理 |
|:---|:---|:---|
| Token无效 | 文件或环境变量错误 | 检查token并重新认证 |
| 接口权限不足 | Tushare积分不足 | 确认接口权限 |
| 行情缺少最近日期 | 使用了自然日或任务中断 | 按交易日历补抓 |
| 财务最新期只有几十行 | 披露尚未完成 | 保留WARN，后续周更 |
| 股票文件数量少于stock_basic | 未上市、退市或无行情 | 对照上市状态检查 |
| 下游因子未更新 | 周更不自动触发02层 | 手动重建因子层 |
