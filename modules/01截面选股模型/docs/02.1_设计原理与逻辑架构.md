# 02.1 因子层设计原理与逻辑架构
> 定位：把 Tushare 原始行情与完整财务版本转换为日频 PIT 基础宽表和 45 个清洗后因子。
---
## 一、层级职责
因子层负责：
- 个股行情转字段宽表
- 财务三表独立版本选择
- 财务 PIT 对齐和严格 TTM
- 行业宽表构建
- 技术和财务因子计算
- 缺失值、去极值、中性化和标准化
- Tushare 迁移验收

因子层不负责：
- 下载原始数据
- 构建模型标签
- 训练模型
- 生成交易订单

## 四、财务PIT数据流
### 4.1 输入
```text
financial_full/
├── income/{period}.parquet
├── balancesheet/{period}.parquet
├── cashflow/{period}.parquet
└── fina_indicator/{period}.parquet
```

### 4.2 三表独立版本选择
利润表、资产负债表和现金流量表可能存在不同公告时间。

正确逻辑：
1. 每张表独立读取完整公告版本
2. 按 `f_ann_date` 依次更新对应报告期的可用版本
3. 同日冲突保守选择 type 5 调整前原始值
4. 版本从公告后的第一个交易日生效
5. 三表完成各自版本选择后再组合派生字段

禁止：
- 在数据层只保留最早公告
- 先按跨表统一公告日合并再做PIT
- 使用后续修订值回填历史交易日

### 4.3 严格TTM
流量字段：

```text
累计值 → 单季度值 → 最近4个单季度滚动和
```

时点字段：

```text
使用最新已披露报告期末值
```

### 4.4 日频对齐
```text
公告日A                 公告日B
  │                       │
  └── 使用版本A ──────────┘
                          └── 使用版本B
```

只有公告日及之后的交易日可以使用该版本。

## 六、清洗Pipeline
当前逻辑按每日截面独立执行：

```text
原始因子
  │
  ▼
缺失值处理
  │
  ▼
MAD去极值
  │
  ▼
行业/市值中性化
  │
  ▼
Z-Score标准化
```

### 6.1 缺失值
- 高缺失率因子不强行填满
- 可填补值优先使用截面或行业信息
- 缺少必要暴露时允许保留 NaN

### 6.2 MAD去极值
```text
median ± n_mad × MAD
```

### 6.3 中性化
```text
factor ~ industry_dummy + log(market_cap)
```

残差作为中性化因子。

### 6.4 标准化
```text
z = (x - mean) / std
```

只在当日截面内计算，禁止跨全样本统计。

## 七、核心设计决策
### 7.1 One Factor, One File
优势：
- 独立重算
- 独立验证
- 模型自动扫描
- 删除因子不改变其他schema

### 7.2 PIT在因子层
因子层最了解字段属于流量表还是时点表，也能分别处理三表公告版本，因此 PIT 和 TTM 位于本层。

### 7.3 每日截面独立清洗
防止未来交易日参与当日分布参数。

### 7.4 原始值与清洗值分层
基础财务宽表保留经济含义，最终因子宽表用于模型输入。

## 九、未来函数检查点
| 检查项 | 通过标准 |
|:---|:---|
| 财务版本 | 公告日后才能使用 |
| 三表对齐 | 各表先独立选版本 |
| TTM | 只由当时可知季度构成 |
| 去极值 | 每日截面独立 |
| 标准化 | 每日截面独立 |
| 因子末日 | 非前瞻因子可正常有值 |

“最后一天因子非空”不等于泄漏；应根据因子定义判断是否需要未来价格。
