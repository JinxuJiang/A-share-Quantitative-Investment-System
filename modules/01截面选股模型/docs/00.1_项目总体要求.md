# 00.1 项目总体要求
> 截面多因子量化选股系统 - 项目愿景、架构设计与规范标准
---
## 一、项目愿景
### 1.1 核心目标
构建一个可复现、可维护、可快速迭代的 A 股截面多因子选股系统。

系统以 Tushare 为正式数据源，通过 PIT 财务对齐、因子工程、LightGBM Quarterly PIT V2 和双轨回测，捕捉因子与未来收益之间的非线性关系。

系统应支持：
- 数据、因子、模型、回测和正式发布分层演进
- 新因子、新模型和新组合约束的低成本接入
- 历史信号冻结和每周增量更新
- 从原始数据到正式 Alpha release 的完整追溯

### 1.2 核心准则
> 逻辑领先于代码，相关性服务于因果。

- 每个因子必须有清晰的经济学或行为金融逻辑
- 所有财务数据必须遵守 Point-in-Time 可知性
- 标签和成交假设必须可执行
- 历史预测不得因后续重训被无声覆盖
- 调参结果、正式配置和实验产物必须可追溯
- 回测必须明确区分已实现约束与计划中约束

## 二、系统架构
整个系统分为五个核心模块，遵循存算分离和低耦合原则：

```text
Tushare
   │
   ▼
Module 1                 Module 2
Data Engine  ──────────→ Alpha Factory
数据搬运与原始存储         PIT/TTM与因子清洗
   │                         │
   └────────────┬────────────┘
                ▼
             Module 3
           Alpha Combiner
       Quarterly PIT V2训练
                │
                ▼
             Module 4
       Analysis & Backtest
          因子分析与回测
                │
                ▼
             Module 5
          Alpha Publisher
      正式发布、审计与下游契约
```

### 2.1 模块职责
| 模块 | 英文名 | 核心职责 | 当前关键技术 |
|:---|:---|:---|:---|
| 模块1 | Data Engine | 原始数据搬运、复权和状态数据构建 | Tushare Pro、Parquet、断点续跑、等比前复权 |
| 模块2 | Alpha Factory | PIT/TTM、因子计算和截面清洗 | 45个因子、MAD、OLS中性化、Z-Score |
| 模块3 | Alpha Combiner | 非线性训练、调参、预测与融合 | LightGBM、Quarterly PIT V2、Freeze |
| 模块4 | Analysis & Backtest | 因子检验、策略回测和候选信号 | Alphalens、Backtrader、月度调仓 |
| 模块5 | Alpha Publisher | 发布已验收的正式截面 Alpha | Parquet、manifest、SHA256、current |

### 2.2 模块详解
#### Module 1: Data Engine（数据引擎）
职责：将 Tushare 的行情、复权因子、财务四表、ST、停牌和元数据可靠落盘。

关键设计：
- 行情按交易日抓取，原始分片支持断点续跑
- 使用 `raw_price × adj_factor / latest_adj_factor` 构建等比前复权价格
- 财务数据按表和报告期保存完整原始版本
- PIT 版本选择留给因子层，数据层不提前丢弃修订版本
- 下载完成后执行完整性、覆盖度和分区验证

#### Module 2: Alpha Factory（因子工厂）
职责：将原始数据转换为可训练的日频宽表与清洗后因子。

关键设计：
- 财务三表分别按公告时间选择当时可知版本
- 流量类字段严格计算 TTM，时点类字段使用最新已披露期末值
- One Factor, One File
- 当前包含 21 个技术因子和 24 个财务因子
- 清洗顺序保持明确：缺失值、去极值、中性化、标准化

#### Module 3: Alpha Combiner（模型训练与集成）
职责：使用截面机器学习模型生成连续 PIT 预测链。

关键设计：
- 正式训练入口为 `main_train_v2.py`
- 每个自然季度训练一个固定模型
- open-to-open 标签从 T+1 开盘开始计算
- 训练、验证和预测之间保留 `horizon + 1` 个交易日 Gap
- Freeze 模式复用季度模型，只追加缺失预测
- 5d/20d/60d 模型可使用滞后历史 IC 进行融合
- V1 Walk-forward 代码已经退役

#### Module 4: Analysis & Backtest（分析与回测）
职责：将预测分数转换为因子评价、回测结果和候选调仓信号。

当前实现：
- Alphalens 已兼容 V2 单一预测链
- Backtrader 支持读取 V2 主预测文件
- 月度首个交易日调仓、主板过滤、涨停过滤、ST过滤、等权仓位和止损

当前限制：
- Backtrader 使用 Tushare 正式 ST 状态文件
- V2 使用单一 PIT 预测链，不再维护独立 live 预测文件
- 组合优化、行业中性和换手率约束尚未正式接入主链路

#### Module 5: Alpha Publisher（输出层）
职责：把已完成训练和回测验收的实验发布为后续仓库可稳定读取的正式 Alpha。

关键设计：
- 只读取训练实验的 `config.yaml` 和 `smoothed_predictions.parquet`
- 发布文件不包含 `actual_return`
- 历史 release 不可覆盖
- `current.json` 明确指向当前默认正式版本
- 后续组合仓库通过文件契约读取，不导入训练层内部代码

## 四、各模块架构设计
### 4.1 Module 2: Alpha Factory 架构
```text
Tushare原始层
    │
    ├─ 行情 ─────────────→ 市场宽表
    │
    └─ 财务完整版本
           │
           ▼
     PIT版本选择 + TTM
           │
           ▼
      技术/财务因子
           │
           ▼
缺失值 → MAD → 中性化 → Z-Score
           │
           ▼
  factors/{family}/{factor}.parquet
```

设计目标：
- 因子生成逻辑与数据下载逻辑解耦
- 每个因子可以独立重算和验收
- 财务数据修订不破坏历史可知性
- 因子值、索引和股票列保持统一

### 4.2 Module 3: Alpha Combiner 架构
```text
DataConstructorV1
特征X + open-to-open标签y
          │
          ▼
QuarterlySplitterV2
季度训练/验证/预测边界
          │
          ▼
QuarterlyTrainerV2
LightGBM季度模型
          │
          ├─ predictions.parquet
          ├─ smoothed_predictions.parquet
          ├─ summary.parquet
          ├─ models/
          └─ state/freeze_manifest.json
```

`data_constructor_v1.py` 仅保留历史命名，仍是 V2 当前共用的数据构造实现。

### 4.3 Module 4: Analysis & Backtest 架构
```text
predictions.parquet
       │
       ├─ Alphalens ──→ IC/IR、分层收益、稳定性
       │
       └─ Backtrader ─→ 调仓、成交、成本、止损、净值
```

第四层在正式验收时必须同时满足：
- 信号数据来自 V2 PIT 预测链
- ST 状态来自 Tushare 正式路径
- 不使用未来不可知的成交信息生成选股分数
- 报告明确列出实际启用的成本和约束

## 五、数据标准
### 5.1 行情数据标准
| 属性 | 规范 |
|:---|:---|
| 来源 | Tushare `daily`、`adj_factor`、`daily_basic` |
| 频率 | 日频 |
| 复权 | 等比前复权 |
| 关键字段 | time、open、high、low、close、volume、amount |
| 股票代码 | `000001.SZ` / `600000.SH` / `430xxx.BJ` |
| 存储 | 原始层按股票，因子层按字段宽表 |

### 5.2 财务数据标准
| 属性 | 规范 |
|:---|:---|
| 原始表 | income、balancesheet、cashflow、fina_indicator |
| 报告期 | `end_date` |
| 公告时间 | `ann_date` / `f_ann_date` |
| PIT原则 | 只使用交易日当时已经公告的版本 |
| 流量字段 | 严格 TTM |
| 时点字段 | 最新已披露期末值 |
| 原始存储 | 按表、按报告期分区 |

### 5.3 元数据标准
| 属性 | 规范 |
|:---|:---|
| 股票基础信息 | `stock_info.parquet` |
| 行业映射 | `industry_map.csv` |
| 交易日历 | Tushare `trade_cal` |
| 停牌状态 | `suspend_status.parquet` |

### 5.4 ST状态数据标准
| 属性 | 规范 |
|:---|:---|
| 来源 | Tushare `stock_st` |
| 存储 | `01数据/data/tushare_data/st_status.parquet` |
| 格式 | 宽表：index=time，columns=stock_codes |
| 状态值 | 0=正常，1=ST |
| 历史覆盖 | 2016-08-09 起；更早为空属于数据源限制 |
| 用途 | 训练、预测和回测股票池过滤 |

### 5.5 数据检验标准
分层检验：
1. 数据层检查下载覆盖、分区完整性、状态表日期和样本最新日
2. 因子层检查 PIT 版本选择、TTM、轴一致性和因子值
3. 训练层检查标签时点、Gap、季度切分和 Freeze 一致性
4. 回测层检查信号时点、成交假设、成本和状态数据来源

检验状态统一使用：
- PASS：满足要求
- WARN：当前可解释但需要关注
- FAIL：结果不可进入下一层
