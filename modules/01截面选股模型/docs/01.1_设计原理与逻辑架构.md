# 01.1 数据层设计原理与逻辑架构
> 定位：从 Tushare 下载行情、财务、状态和元数据，形成可断点续跑、可验证的本地 Parquet 原始层。
---
## 一、层级职责
数据层只负责数据搬运、格式统一、复权重建和原始版本保存。

负责：
- 股票基础信息、交易日历和行业映射
- 日行情、复权因子和每日指标
- income、balancesheet、cashflow、fina_indicator 完整版本
- ST 和停牌状态
- 原始分片、兼容文件、更新日志和验证报告

不负责：
- 财务 PIT 版本选择
- TTM 计算
- 因子计算和截面清洗
- 模型训练和回测

这些逻辑分别属于 02、03、04 层。

## 三、数据流向
### 3.1 行情
```text
Tushare daily / adj_factor / daily_basic
              │
              ▼
按交易日全市场抓取
              │
              ▼
raw/market/ 单文件或分片
              │
              ▼
按股票聚合 + 等比前复权
              │
              ▼
market_data/{code}.parquet
```

### 3.2 财务
```text
Tushare 财务四表
      │
      ▼
按表、按报告期抓取
      │
      ▼
保留 report_type=1/5 和公告版本
      │
      ▼
financial_full/{table}/{period}.parquet
```

数据层不在这里选“最终版本”。同一报告期的修订记录全部保留，供因子层按交易日进行 PIT 选择。

### 3.3 状态和元数据
```text
stock_basic / trade_cal / index_classify
        └─→ stock_info + trade_cal + industry_map

stock_st / suspend_d
        └─→ st_status + suspend_status
```

## 四、输入输出契约
### 4.1 上游输入
| 接口族 | 主要用途 |
|:---|:---|
| `daily` | 未复权 OHLCV |
| `adj_factor` | 复权因子 |
| `daily_basic` | 市值、换手和估值基础字段 |
| `income` | 利润表 |
| `balancesheet` | 资产负债表 |
| `cashflow` | 现金流量表 |
| `fina_indicator` | 财务指标表 |
| `stock_basic` | 股票基础信息 |
| `trade_cal` | 交易日历 |
| `stock_st` | ST状态 |
| `suspend_d` | 停牌状态 |

前置条件：
- 有效 Tushare Pro token
- 相应接口积分权限
- 网络可访问 Tushare

### 4.2 下游输出
| 数据 | 路径 | 格式 |
|:---|:---|:---|
| 个股行情 | `data/tushare_data/market_data/{code}.parquet` | 长表 |
| 财务完整版本 | `data/tushare_data/financial_full/{table}/{period}.parquet` | 分区长表 |
| ST状态 | `data/tushare_data/st_status.parquet` | 日×股票宽表 |
| 停牌状态 | `data/tushare_data/suspend_status.parquet` | 日×股票宽表 |
| 股票信息 | `data/tushare_data/stock_info.parquet` | 元数据表 |
| 行业映射 | `data/tushare_data/industry_map.csv` | code→industry |
| 更新记录 | `data/tushare_data/update_log.json` | JSON |
| 验证报告 | `data/tushare_data/logs/` | JSON/Markdown |

## 五、核心设计决策
### 5.1 为什么使用 Tushare
- 数据接口适合按日全市场批量抓取
- 行情、财务、状态和元数据可以统一管理
- 财务接口能保留公告版本和报告类型
- 不依赖本地交易终端持续在线

### 5.2 为什么保存原始分片
Tushare 行情接口以交易日全市场为自然抓取单位，而因子层需要按字段或按股票读取。

原始分片用于：
- 断点续跑
- 复权因子变化后的重建
- 排查单日接口异常
- 避免失败后重新下载全部历史

### 5.3 为什么使用等比前复权
```text
adjusted_price(t) = raw_price(t) × adj_factor(t) / latest_adj_factor
```

优点：
- 最新价格与未复权价格一致
- 避免传统差值复权产生负价格
- 历史收益序列连续

注意：最新复权因子变化会让历史复权价格整体漂移，因此数据更新后可能需要重建兼容行情。

### 5.4 为什么财务按表和报告期分区
- 下载接口天然按报告期查询
- 单分区失败可以独立重试
- 新季度披露只更新最新分区
- 因子层可以分别选择三表版本
- 避免过早把不同公告口径合并

### 5.5 为什么使用原子写入
财务和行情文件可能在长时间任务中被中断。先写临时文件再替换目标文件，可以避免留下半个 Parquet。

## 七、边界与潜在问题
### 7.1 财务披露期不完整
最新报告期在披露窗口内只有少量公司数据属于正常现象。数据层应给 WARN，不应把该分区误判为完整横截面。

### 7.2 Tushare积分和限频
不同接口权限、频率和单次返回上限不同。下载器必须限速、分页和重试。

### 7.3 ST历史覆盖
Tushare `stock_st` 历史从 2016-08-09 起，更早日期无法从该接口恢复。

### 7.4 数据层与因子层边界
禁止在数据层按“最早公告”提前去重，否则会丢失财务修订版并破坏后续 PIT 重建。
